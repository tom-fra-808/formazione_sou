Scopo

Utilizzo dei template Jinja all’interno dei playbook Ansible.



Introduzione

I template Jinja sono in grado di generare file in maniera dinamica utilizzando variabili, costrutti condizionali e cicli (https://jinja.palletsprojects.com/en/stable/).

Vediamo un semplice esempio di if-then-else. Supponiamo di aver popolato la variabile fruit:

    {% if fruit in [ 'ananas', 'avocado' ] %}

    Tropical

    {% elif fruit == 'hazelnut' %}

    Dried fruit

    {% endif %}

Supponiamo invece di dover generare dei blocchi ripetuti in un file HTML o XML. Possiamo sfruttare il ciclo nella seguente maniera:

    {% for i in range(1,10) %}

      <p>Number {{i}}</p>

    {% endfor %}

Ora veniamo all’integrazione dei template Jinja con Ansible. Questa avviene attraverso il modulo template:

    - name: Creazione nuovo file da template

      ansible.builtin.template:

        src: /tmp/mytemplate.j2

        dest: /tmp/output.txt

      delegate_to: localhost

Notare come il file venga depositato sull’host dove viene eseguito il playbook.

Le variabili all’interno del template sono quelle impostate dal playbook. Possono essere definite staticamente nel codice o fornite da linea di comando attraverso l’opzione —extra-vars.

A questo punto il contenuto del nuovo file generato può essere utilizzato per popolare un file su una macchina target attraverso l’utilizzo del modulo blockinfile. Nel nostro esempio il contenuto viene messo in “append” alla fine del file:

      - name: append block to file

        ansible.builtin.blockinfile:

          path: /home/myfile.txt

          block: “{{ lookup(‘ansible.builtin.file',

                                 ‘/tmp/output.txt') }}"

          insertafter: EOF

          create: yes

Obiettivo

Creare un playbook Ansible che aggiunga in append sul file /etc/security/limits.conf alcuni settings per un’utente. In ambiente di produzione dobbiamo imporre un numero massimo di file aperti pari a 10000, mentre in ambiente di collaudo e sviluppo 1000.
Supponiamo che in /etc/security/access.conf ci sia un’ultima riga che impedisce l’accesso agli utenti non esplicitamente autorizzati (“- : ALL : ALL”). Creare un playbook Ansible che aggiunga una lista di utenti in whitelist anteponendosi a tale riga (hint: utilizzare l’opzione insertbefore del modulo blockinfile).

File yaml rappresentante un pod o un deployment Kubernetes
Virtual host di apache
